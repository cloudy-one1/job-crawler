总体评价

作为软件综合实践课程项目，job-crawler 属于优秀档次（复验后 8.4/10，初评 8.1）。它不是一个只跑通单一脚本的作业，而是一条从真实数据采集、清洗入库、多维统计、机器学习建模到 LLM 应用与 Web 展示的完整工程链路，且每一层都有对应的工程化考量：测试自给自足（临时库夹具，不依赖本地数据库）、CI 三版本矩阵、Docker 分离采集与展示、CSRF / 限流 / 口令保护、多级缓存与空库容错。复测进一步验证了两件文档里写着、代码里容易悄悄破掉的事：分层依赖全量扫描无一处向上引用，17 条路由 GET 冒烟无一条 5xx。

距离更高分的差距不在功能数量，而在数据口径的严谨性——这一点已修复并复验。51job 改用「X年及以上」口径后，分析层与建模层各自保留的旧映射表失效：交叉图 88.4% 的岗位、分类器 57.4% 的样本被兜底进「经验不限」，成长曲线碎成 19 个档位。修复后口径集中在 data/exper_parser.py 一处，/chart 各经验档均值恢复单调递增，分类器 macro-F1 从 0.361 升到 0.386。

这次修复暴露的问题比 bug 本身更值得写进报告：250 条用例全绿却接不住它，因为夹具里的经验取值全是旧写法。测试覆盖的是代码路径，不等于线上数据分布——所以本次同时把夹具换成真实分布，并把库中出现过的 36 种写法固化成映射表断言，下次口径再变会先由测试报出来。

提交/分享前仍须本人处理两件事：① 在 DeepSeek 与阿里云控制台作废并重新签发 .env 里的两把 Key（复测确认密钥未泄漏到其他任何文件，但落盘即视为暴露，删文件不能撤销）；② data.db 与 cache/ 都被 gitignore，评审若克隆仓库跑起来是空库，按 zip 提交须包含 data.db。
