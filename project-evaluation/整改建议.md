## 二、提交 / 分享前必做（P1）

### 1. 立即轮换两个 API Key

旧 Key 已随目录拷贝暴露，删除 .env 不能消除已泄露的事实。



* **DeepSeek**：登录 `platform.deepseek.com/api_keys` → 删除旧 Key → 创建新 Key

* **通义千问（DashScope）**：登录 `bailian.console.aliyun.com` → API-KEY 管理 → 删除旧 Key → 创建新 Key

* 新 Key 只写入本机 `.env`，`.env.example` 保持 `sk-xxx` 占位

### 2. 对外目录净化

打包前删除以下内容（均在 .gitignore 内，删除不影响源码）：



```
# 在项目根目录执行
Remove-Item -Recurse -Force .env, venv, __pycache__, logs, cache, backups
Remove-Item -Force data.db, AI协作过程记录.docx   # 数据库与过程文档不随作业分发

# 验证：确认 Git 未跟踪任何敏感文件（应无输出）
git ls-files | Select-String "env|db|docx"
```

## 三、本周内完成（P2）

### 3. 消除 cache 版本警告 ✅ 已完成（2026-10-01）



```
Remove-Item -Force cache\*.joblib    # 重启后 /api/warmup 自动重训
```

并建议在分类器 / 聚类的加载函数中，把 `InconsistentVersionWarning` 也纳入 "自动重训" 判定 —— 当前 CHANGELOG 的 `pkg_version` 只识别自定义版本号，未覆盖 sklearn 小版本，所以警告仍在。

### 4. app.py 按 Blueprint 拆分 ✅ 已完成（2026-10-01）

建议结构：



```
routes/
├── pages.py    # /  /list  /job/<id>  /interested
├── chart.py    # /chart  /chart/analyze
├── ml.py       # /ml  /ml/analyze  /ml/cluster/<id>  /ml/salary-predict
├── advice.py   # /advice 及子接口
└── collect.py  # /collect  /toggle_interest
services/
└── cache.py    # 15+ 个缓存字典收敛于此
```

每个蓝图模块内 `bp = Blueprint('ml', __name__)`；app.py 只负责 `app.register_blueprint(bp)` 与安全初始化，可降到 200 行以内。

### 5. 生产部署两处加固 ✅ 已完成（2026-10-01）



* **Flask-Limiter** 默认内存存储，多 worker 时限流会各自计数、实际失效，应配置 `storage_uri="redis://localhost:6379"`（或其他持久后端）；

* 不要用 `python app.py` 的开发服务器上生产：Linux 用 gunicorn，Windows 用 `waitress-serve --port=5000 app:app`。
